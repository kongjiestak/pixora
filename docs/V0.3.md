# V0.3: developer and personal information

English / 简体中文 — development build, not a stable release.

## Implemented / 本轮范围

- Public GitHub repository statistics and its five latest Actions runs. No GitHub token is accepted or forwarded. Stars and open issues **including PRs** are separate numeric metrics. This is not CI control, PR review or private repository access.
- RSS 2.0 / Atom: first ten titled entries in feed order, safe HTTPS links, inert text. HTML, images and scripts are not rendered. Redirects are not followed; configure the final HTTPS feed URL. No arbitrary feed configuration API exists.
- Local JSON task file: pending/completed counts, first ten pending titles, maximum 200 tasks. Administrator-maintained read-only integration; no task editor, completion action or third-party sync yet. Missing configuration is unavailable; invalid input/upstream failures are error with no fabricated metrics.
- Three new scoped providers (`github`, `rss`, `tasks`), private Widgets, developer/personal dashboard tabs and display presets, EN/ZH. Existing device scopes do not expand automatically. Shared display filters these widgets and clears private data; create narrow provider/mode tokens for server enforcement. Field-level public sharing remains future work.

## Configure / 配置

Install normally, then set collector-only environment variables:

```sh
PIXORA_GITHUB_REPOSITORY=kongjiestak/pixora
PIXORA_RSS_URL=https://github.blog/changelog/feed/
PIXORA_TASKS_FILE=/private/path/tasks.json
# Also set PIXORA_SERVER and its write token, as with other collectors.
pixora-collect --plugin information --interval 600 --max-retry-delay 600
# Or independently: --plugin github / rss / tasks --once
```

Task file format (schema example, not real user tasks):

```json
[{"title":"Your own task","done":false}]
```

Do not place private tasks or upstream credentials in the repository. Store the task file with least-privilege read access. Collector errors do not upload raw responses, local paths, task source files or cookies. Only configured task titles/counts are uploaded, so the server and authorized screens can read that personal data. Remove titles you do not want on the server. GitHub/RSS content comes from upstream and can be misleading; no automation executes it.

RSS URL configuration is trusted administrator input. HTTPS/public DNS checks, response cap (1 MiB), no redirects, no ambient proxy/credentials, and XML DTD/entity rejection reduce exposure; they are not a DNS-rebinding-proof egress sandbox. Run with network restrictions appropriate for untrusted operators. No public URL-fetch endpoint is exposed. Third-party links open only on user click with no referrer; external privacy terms apply.

Provision a **new** capability rather than expanding old phones:

```sh
pixora-device create --name information-screen --provider github --provider rss --provider tasks --mode real --days 30
```

Provider access is coarse-grained, covering all entities for the granted provider. No per-task/entity permission or server device editor is claimed. HTTPS pairing output is private.

## Contract / Compatibility

Observation v2 gains optional `entries` (maximum 10): bounded title/detail and optional credential-free HTTPS URL. Entries are plain text; known numeric metrics remain required for status `ok`. Failures cannot contain metrics or entries. Existing v2 rows without entries remain readable; SQLite stays at version 2 and v1 quota clients remain compatible. No reconstruction of missing past feed/task history. Current GitHub status describes the last successful fetch, never a live guarantee; expiration and disconnected state remain visible.

Before deploying, back up SQLite and retain the V0.2 image. For full rollback stop all writers and restore the independent pre-V0.3 backup: new provider grants/entries should not be treated as part of the V0.2 contract. Restore loses post-backup observations and sessions. No stable Release is created by this increment.

## Acceptance / 验收

Tests cover input bounds, unsafe XML/links, missing configuration, source errors, public-only GitHub requests without credentials, redirect rejection, new provider scope isolation/revocation and shared-screen exclusions. Real API, deployment, browser and phone results are recorded separately; fixture tests alone are not end-to-end proof.
