# V0.5 ESP32 屏幕完善与验收

适用 Waveshare ESP32-S3-Touch-AMOLED-2.16；开发分支，不代表稳定版验收。

## 已实现

- Orbit 双环外围紧凑显示时分、月日/星期、城市/当前天气及连接状态。时间由 SNTP 或签名 Mac USB 帧校准，随后设备本地走时。无可信时间显示 `--:--`。
- 独立床头数字时钟页：左右滑动切页，本机保存上次页面，无自动轮播。夜间调暗不能保证消除烧屏；整页像素位移尚未实现。
- Settings → Screen / Clock：亮度 20–100%、夜间调暗、时区、旋转。夜间模式按本机显示时区 22:00–07:00 且闲置15秒时降至8%；触摸后恢复设置亮度。
- 时区与天气城市独立。本轮可选 UTC+08 / UTC / UTC-05 固定偏移，**不是带夏令时规则的城市时区**。内部时间和额度解析始终 UTC。
- 旋转提供0/90/180/270度，保存成功后重启；由适配器旋转绘制及对应触摸映射。本轮没有自动感应旋转。
- 首页闲置15秒隐藏小齿轮入口；透明触摸层消费首次点击以唤醒，下一次点击才执行操作。设置页不自动隐藏。
- 二级菜单有 Back，密码输入页也有显式 Back / 键盘 X；取消不提交凭据。连接过程中 Back 仅离开进度页，已提交的连接仍在后台完成。
- 移除持续绕圈，只在额度改变时做350ms局部过渡，可关闭动效。相同文字不反复重绘。每10次实际绘制刷新记录均值/最大耗时；此指标不是面板物理刷新率，也不能代替视觉流畅度验收。

## 数据与权限

Wi-Fi与Mac桥接均用同一设备令牌读取既有 `/api/v1/device` 和 `/api/v2/observations`，保持TLS证书验证且禁止重定向。USB只加入天气观察，不传递其他个人观察。源为 Open-Meteo.com，CC BY 4.0；来源页保留署名。

仅展示授权返回的真实天气，校验单位、范围、采集/模型时间及到期时间。无天气权限与天气不可用分别提示；天气失败不会抹掉额度。撤销清空数据。城市沿用服务端默认采集城市；**本轮未加入ESP本机城市搜索、手机本地城市偏好同步或多天气源**。

## 实物验收（待用户确认）

1. 启动后核对时分、日期星期、天气及额度，检查外围文字无裁切/覆盖。
2. 左右滑动切页并重启，确认记住页面；左右滑动可返回。
3. 每一级菜单测试Back；Wi-Fi密码页取消，原连接仍保留。
4. Settings → Screen / Clock修改亮度及夜间开关，重启保留；夜间时段闲置后变暗、首触只唤醒。
5. Rotation每点一次会保存并重启；四方向分别验证文字方向与Settings/Back触摸位置，最终回0度。
6. 观察额度变化时短过渡是否舒适；关闭动效后无过渡。静态显示不应持续绕圈。
7. 拔插USB自动恢复、断网/撤销状态及持续运行另外验收，不以构建/ACK代替实物画面验收。

未实现：自动旋转、时区夏令时、可编辑夜间时段、蓝牙、多Wi-Fi管理。热点直连兼容问题仍单独跟踪。

## 实物照片反馈后的表盘修订

上一版的角落文字与圆环/底部标签相交，数字时钟比例偏小；该版视觉验收不通过。改为：

- 双环直径360/320，居中；额度、短/长窗口与重置说明全部在内圈内，不再常驻采集年龄等长文案。
- 时间/日期/天气/连接四段短文字以半径216沿弧排字，每字按字体实际宽度定位置和切线角度，下半圆反向排布以保持正向阅读。首页用ASCII短信息，城市中文全名与数据来源放连接详情，避免逐字旋转UTF-8中文字节。
- 床头页改为60刻度、12/3/6/9、时分针的模拟钟盘，同样采用外缘信息。指针按分钟更新，不做连续秒针动画。
- 移除首页两个矩形按钮；左右滑动切页，长按空白或额度中心进入设置，小齿轮辅助发现。首次闲置触摸仍只唤醒。二级菜单保留Back；点天气/连接弧字进入来源详情。
- 实物重点检查四段弧字方向、内外圈间距、刻度/指针、滑动与长按、旋转后触摸。照片反馈后的新布局尚需重新验收，不能沿用前版API/ACK结论。


## 数字钟与设置切换修复（当前验收版本）

用户反馈进入设置无法操作；照片中的前版设置页不记为验收通过。切页改为LVGL异步任务，重建前重置输入/等待抬手，待切换期间禁止更新已失效的首页对象，并清空旧控件引用。软件模拟验证不能证明实物触控已修复。

按最新要求，床头页改回大号数字时分、每秒变化秒数、每秒明暗切换冒号（动效关闭时常亮，秒数继续）。不再使用指针盘；外围弧形信息保留。

设置 → Screen / Clock → Language / English 可切到简体中文；中文入口为“屏幕与时钟 → 语言 / 简体中文”。语言、主题、时钟页面均保存在本机。界面及配网消息有中英文映射，弧字按UTF-8码点排版；Noto CJK子集补齐界面字形，任意SSID仍可能有未覆盖字形。后台/品牌/协议名保持原样。

新增真实LVGL软件触摸回归（ASan/UBSan），覆盖四轮Paper主题页面往返、语言保存及数字钟冒号节奏；另输出软件帧缓冲供布局检查。**仍需用户验证实机Settings/Back、中英文重启保存、秒数/冒号及触摸旋转**。


## 三屏缓存、触摸补读与本机任务机器人（最新）

用户明确反馈“明显停顿”和“完全无响应”两种情况均存在，故先前版本的切页/触控验收仍不通过。

- 外围弧字由18px增至24px，半径214，新增对应OFL中文子集，内圈不变。
- 三个首页（额度、数字钟、机器人）启动时预建、切页复用，主题/强调色/语言变化才失效重建。新增缓存页面连续18次滑动、设置/主题往返及数据过期的原生LVGL回归，查询仅匹配可见控件。
- BSP触摸适配器仅有IRQ时读取新点，缺中断可能保留按下状态。本轮通过适配器公开的notify接口每33ms补充触点读取，不修改上游驱动；是否解决实物无响应仍待用户验证。
- 闲置仅将齿轮淡化，不再用全屏遮罩吞掉第一次点击/滑动；首触可直接切页或进入设置，夜间亮度随触摸恢复。配网等操作仍需二级确认。
- 新增原创Pixora Bot，跟随同一主题/强调色，非官方Codex吉祥物。任务进行中时手臂交替动作；空闲、错误、未知分别显示，关闭动效时保持状态文字但不动。未知状态不伪装工作。

### 任务信号与隐私边界

`clients/codex_activity.py` 是实验性的Mac本地Codex rollout事件适配器：每次仅检查最近12个本地记录的有界尾部，使用 `task_started/task_complete/turn_aborted/task_failed` 元数据，忽略消息/工具内容。记录90秒无更新即不再作为工作依据，显示端信号15秒过期。该状态只代表这台Mac被观察到的近期任务，不是账户全设备或家庭PVE的全局状态，也不等于CPU持续执行；持续等待或日志格式变化可能显示未知。

桥接配置 `activity_enabled` 默认false，用户选择后仅向同一已认证USB屏幕传source/state/observed_at/expires_at，不传线程ID、标题、目录、提示词或原始记录，不上传VPS。额度/天气HTTPS仍30秒读取，本地签名帧在启用活动时每5秒发送。Wi-Fi直连未接入本机任务信号时机器人显示未知。

官方App Server有独立运行状态/等待标记事件，可作为后续连接器；当前适配器没有假称订阅其他桌面进程的App Server流。参考：https://learn.chatgpt.com/docs/app-server

实物验收：连续往返三屏和Settings/Back；闲置后第一次滑动；中英文/主题保持；观察Mac任务完成后的休息状态和启动任务后的工作状态。构建、软件模拟、真实本地事件读取和USB ACK均不能代替这组用户验收。


### 实物内存故障追加修复

三屏首轮实物检查曾出现“界面启动但无USB握手”；后台任务改为界面预热前分配栈并检查创建结果，随后前台握手/真实帧ACK通过。串口私密诊断进一步发现 SPI `Failed to allocate priv TX buffer`，因此不能把握手通过当作刷屏正常。

后续将LVGL malloc/realloc集中到PSRAM（不回退侵占内部DMA内存），驱动/任务保持内部内存。配置使用 `CONFIG_LV_USE_CUSTOM_MALLOC`，实现位于 `ui_memory.c`。必须在实物启动/切页期间检查SPI错误是否消失，并重新验收触控；主机CLIB内存模拟不能证明ESP DMA资源健康。

### 2026-10-23 触摸错误路径修复（仍待实机验收）

用户在PSRAM版复测仍出现完全无响应，触控验收未通过。约45秒私密串口诊断中，真实USB帧持续ACK且DMA错误、panic、assert计数均为0；这只能确认该观察窗口，不能证明触控正常。

代码检查发现CST9217在无效ACK时保留旧触点，而默认适配层忽略read_data错误，可能持续向LVGL报告按住。应用通过公开custom_touch_read接口检查读取结果，错误时清空count并返回错误，让适配层发布释放状态；保留33ms补读通知。每300次读取只记录读取/错误/按下/释放计数，不记录坐标、网络或凭据。此修改未更改托管组件。ESP-IDF构建通过；是否解决完全无响应必须再次进行物理触摸验收。

### 2026-10-23 第二轮触控：补齐控制器报告确认

0da59c3由用户复测仍完全无响应，因此不能算触控修复完成。应用继续运行且USB/显示刷新持续，不代表输入正常。核对SensorLib CST92xx源实现发现，读取D000报告后需要写D000AB确认（包括空或无效报告）；当前托管CST9217驱动缺少该写入。应用自定义读取回调在总线读取成功或标记无效时补确认，总线失败不盲写；保留错误释放与计数，另计ack_errors。托管组件未被修改。参考：https://github.com/lewisxhe/SensorLib/blob/master/src/touch/TouchDrvCST92xx.cpp 。此为有源码依据的协议修复，最终仍需要实物连续触摸确认，不能仅凭构建/ACK认定根因解决。

### 旋转冲突审计：暂停推断式映射调整
