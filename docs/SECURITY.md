# Pixora security / 安全

Single-user, single trust domain prototype. A stolen write token can forge observations; `source` is a trusted collector assertion, not cryptographic provenance. The legacy read token grants all currently stored observations until disabled. Independent display tokens enforce provider/mode scope, expiry and live revocation; see DEVICES.md. No per-field or tenant isolation is claimed. Display sign-out clears page credentials and pending requests; it is not a server ACL. V0.4 adds restrictive policy projections, described in V0.4.md.

Use distinct random 32+ character `PIXORA_READ_TOKEN` and `PIXORA_WRITE_TOKEN`. Bearer header only, no query tokens; no CORS by default. Raw pairing/manual tokens and observations remain in page memory, settings/locale in localStorage. Optional persistent device sessions use a Secure, HttpOnly, SameSite=Strict host-only cookie, with only its SHA256 digest stored server-side. Sessions are capped at 30 days and device expiry; live device revocation applies on every request. Session creation/logout require exact same-origin HTTPS Origin; only scoped device tokens can create sessions. Sign-out revokes the current browser session; device CLI revocation invalidates all its sessions. See device-sessions.md. PWA caches only public assets, never API. Legacy token rotation requires restart and affects every screen sharing it. Scoped device revocation takes effect on the next request. No system/device automation control API is implemented. Separate administrator device management is described in ADMIN.md.

Codex authentication stays with the installed CLI. Pixora does not open auth.json, collect cookies/prompts or send raw RPC. The query can cause normal CLI credential refresh. `--print-only` outputs account observations: keep private. Snapshot fields/body size and time ordering are validated; no account data is distributed. Backups and credentials must be separate. The legacy `APM_*` fallback is supported; avoid conflicting variables.

Default service binds loopback. HTTPS is required outside loopback, except an explicitly trusted encrypted private VPN with collector `--allow-private-http`. Use a reverse proxy with TLS, body/connection/rate limits, and logs that exclude Authorization. Do not expose Codex app-server. The app does not include internet-scale rate limiting, distributed abuse protection or complete endpoint isolation.

Vulnerability reporting: contact the owner via [GitHub profile](https://github.com/kongjiestak) first, without disclosing secrets. A dedicated confidential intake channel is not established and no SLA is promised. If no private contact is available, open a minimal issue requesting a private channel; do not include exploit credentials or sensitive data. Do not claim a security audit or production hardening from these checks.
