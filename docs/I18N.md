# Internationalization / 国际化

Only `en-US` and `zh-CN` are currently translated. Vue I18n 11 Composition API; stable nested keys live in `web/src/locales/*.json`. Browser languages are checked in order; saved supported choice wins; unsupported languages fall back to English. Manual choice is persisted in `pixora-locale`; blocked storage degrades to a session preference. HTML `lang` updates on switching. Both current locales are LTR; an RTL locale is not implemented yet.

All user-facing UI strings use keys. Product names and raw protocol bucket identifiers are data, not translated sentences. The backend returns `reason_code`; unknown legacy reason strings are not displayed verbatim. Do not translate stored identifiers, status values, provider keys or timestamps. An explicit Demo Data label is always translated and shown on demo cards.

Date/time/number/percent/currency formatting uses Intl and the active locale; timestamps are UTC in transport and rendered in the display device's local time zone. Locale does not select a different geographical time zone. No currency/billing widget is currently implemented; currency helper is available and tested. Future widgets must avoid concatenated localized sentences and consider logical CSS/RTL.

To contribute: add matching keys to both current locale files, use `{parameter}` placeholders consistently, run `npm --prefix web test` and build. Tests verify key parity, actual Vue I18n switch/fallback, locale selection, disabled storage, formatting and widget title keys. Do not claim a new language supported until every key is translated and the UI is reviewed.

中文说明：当前完整目标为英美英语和简体中文；浏览器检测、手动切换、英语回退和偏好持久化已实现。日期使用设备本地时区，区域语言不等于地理时区。服务器传结构化原因码，不把旧中文原因原文直接放入英文界面。翻译时保持两份 JSON 键一致，不拼接句子，不翻译协议标识。新增 RTL 语言仍需实现方向与布局验证。
