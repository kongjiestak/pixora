# V0.5 first-screen prototype

[English](V0.5.md) | [简体中文](V0.5.zh-CN.md)

The roadmap now focuses on self-hosted cross-device AI status/reminders. The old personal-information V0.5 scope is cancelled; existing weather/clock/system/GitHub/RSS remain optional. V0.4 was accepted by the owner. New milestones: V0.5 first ESP32 + phone onboarding, V0.6 actual activity/minimal alerts + Apple Watch 8 notification validation, V0.7 novice usability/recovery, V1.0 stable contracts and delivery. Native wearable apps and broad band compatibility are not promised.

Source for an original ESP-IDF/LVGL client is in [firmware/esp32](../firmware/esp32/README.md). Its first gate is a reproducible build and exact quota parsing, not a claim of supported hardware. It reuses the existing HTTPS device API and independent read scope; no new server endpoint, upstream credential storage or production server deployment is necessary. The initial display omits web theme/profile/weather synchronization and uses English labels; setup is bilingual and still requires manual AP-page opening.

An attached Waveshare ESP32-S3-Touch-AMOLED-2.16 was identified as ESP32-S3 rev0.2, 16 MiB Flash and 8 MiB embedded PSRAM. The full original flash was backed up and device-digest verified. Security info reported Secure Boot and Flash Encryption disabled; no fuses or security flags were changed. Exact identifiers, backups and deployment credentials are private, outside this repository.

Current tests: production C quota parser passes host Address/UndefinedBehavior Sanitizers and matches a real authorized VPS Codex response. Build and hardware/phone gates must be tracked separately. Do not carry forward older Web/PWA acceptance as ESP32 acceptance.

Local ESP-IDF v5.5.5 build passed: application image 1,574,768 bytes (0x180770), approximately 75% of its 6 MiB partition free. No device flash write yet; physical display/touch/setup acceptance remains pending.
